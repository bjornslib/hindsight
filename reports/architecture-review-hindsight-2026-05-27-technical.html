Security Findings

9 findings: 1 P1 (no CORS or rate limiting), 6 P2, 1 P3, 1 PASS. The default deployment is open to cross-origin requests and has no per-second rate limiting. Individual findings are moderate in isolation but compound when combined (SEC-01 + SEC-03 + SEC-09 = unauthenticated access with schema leakage).

P1 SEC-03 — No CORS configuration or rate limiting on API endpoints → Founder view confirmed P1

File: hindsight-api/hindsight_api/api/http.py:1797

Technical description: The FastAPI create_app function does not add CORSMiddleware or any rate limiting middleware. grep for CORS, CORSMiddleware, rate_limit, and slowapi across the entire hindsight_api/ directory returns zero results. The only middleware added is http_metrics_middleware (Prometheus telemetry).

Compound risk: Combined with SEC-01 (default no-auth) and SEC-09 (raw exception messages), any internet-reachable deployment is fully exposed — any origin can call the API, with unlimited request frequency, and receive database schema details in error responses.

Internal backpressure exists but is insufficient: Internal semaphores (_global_llm_semaphore = 32, _search_semaphore = 32, _put_semaphore = 5) provide process-level concurrency limits but are NOT per-tenant and NOT per-second rate limits. A single tenant can consume all semaphore slots.

hindsight-api/hindsight_api/api/http.py:1797
1797 app = FastAPI(title=..., lifespan=lifespan)
1798 app.add_middleware(http_metrics_middleware) # Only middleware — no CORS, no rate limiting

Recommended fix: Add CORSMiddleware with explicit allowed_origins. Add rate limiting via slowapi. Make both configurable via environment variables.

P2 SEC-01 — DefaultTenantExtension allows unauthenticated access to all data → Founder view downgraded from P1

File: hindsight-api/hindsight_api/extensions/builtin/tenant.py:26

Technical description: DefaultTenantExtension.authenticate() returns TenantContext(schema_name=self._schema) without any authentication check. When no tenant extension is configured, all requests are served on the default schema with no API key or token validation.

Review note: Downgraded from P1 because DefaultTenantExtension is documented as no-auth single-tenant for development. The real risk is deployment misconfiguration. A startup WARNING log when DefaultTenantExtension is active would be the appropriate remediation.

Recommended fix: Add a startup WARNING log when DefaultTenantExtension is active. Consider requiring explicit opt-in for no-auth mode in production.

P2 SEC-02 — MCP auth can be disabled via environment variable → Founder view downgraded from P1

File: hindsight-api/hindsight_api/extensions/builtin/tenant.py:67

Technical description: ApiKeyTenantExtension has mcp_auth_disabled flag. When set to true/1/yes, authenticate_mcp returns TenantContext without checking the API key. Documented as backward compatibility for MCP transports that provide their own auth layer.

Review note: Downgraded from P1 — explicit opt-in flag (default empty/false). Only needed for stdin-based MCP servers. A startup WARNING when enabled would be appropriate.

Recommended fix: Add a startup WARNING when mcp_auth_disabled is set. Consider deprecating this flag.

P2 SEC-04 — SQL table names constructed via f-string interpolation → Founder view

File: hindsight-api/hindsight_api/engine/memory_engine.py:59 (and 4 other locations)

Technical description: fq_table(table_name) returns f'{schema}.{table_name}' where table_name comes from hardcoded _PROTECTED_TABLES whitelist. The pattern is used in 5 modules (131 call sites total). Current implementation is safe because table names come from whitelist, but f-string interpolation for SQL identifiers is a category error that creates a maintenance hazard.

Recommended fix: Migrate fq_table() to use asyncpg's quote_ident or SQLAlchemy's quote. Document that fq_table() must only be called with hardcoded table names.

P2 SEC-05 — Admin CLI TRUNCATE uses f-string interpolation for schema/table names → Founder view

File: hindsight-api/hindsight_api/admin/cli.py:115

Technical description: Admin CLI uses f-string interpolation for TRUNCATE TABLE {qualified_table} CASCADE and REFRESH MATERIALIZED VIEW. Attack surface is minimal (local admin tool only, schema from config/env, table names from hardcoded lists), but TRUNCATE is destructive and proper identifier quoting is best practice.

Recommended fix: Use asyncpg's quote_ident or validate schema/table names against an allowlist before interpolation.

P2 SEC-07 — Default PostgreSQL password in Helm values → Founder view

File: helm/hindsight/values.yaml:213

Technical description: password: 'hindsight' is the default PostgreSQL password in the Helm chart. Many Kubernetes deployments ship with default values. PostgreSQL is network-accessible within the cluster.

Recommended fix: Remove the default password. Make it required, or generate a random one on install. Add a NOTES.txt warning.

P2 SEC-09 — HTTP 500 responses expose raw exception messages to API clients → Founder view found by spot-check

File: hindsight-api/hindsight_api/api/http.py:1987 (45 instances)

Technical description: http.py contains 45 instances of HTTPException(status_code=500, detail=str(e)) that expose raw Python exception messages to API clients. Database errors (asyncpg.PostgresError) can include table names, column names, constraint names, and schema details. Compounds with SEC-01 (default no-auth) and SEC-03 (no CORS/rate-limiting).

Recommended fix: Add a global exception handler to FastAPI that sanitizes 500 error responses. Replace detail=str(e) with a generic message in production. Log full exceptions server-side (already done).

P3 SEC-06 — dotenv override=True may leak env vars in multi-tenant deployments downgraded from P2

File: hindsight-api/hindsight_api/config.py:17

Technical description: load_dotenv(find_dotenv(usecwd=True), override=True) allows .env values to take precedence over environment variables. Hindsight is single-tenant per process — the multi-tenant framing is incorrect. The pattern is typically desired for local development. In containerized deployments, .env files are not typically mounted.

Review note: Downgraded to P3 — the risk requires local filesystem access and overrides the typical desired direction.

All API keys, database URLs, and service account keys are loaded from environment variables with no hardcoded defaults. _CREDENTIAL_FIELDS clearly marks fields that must never be exposed via API. .env file is in .gitignore.

P2 ARCH-02 — Direct asyncpg SQL in business logic bypasses ORM abstraction → Founder view downgraded from P1

File: hindsight-api/hindsight_api/engine/memory_engine.py

Technical description: MemoryEngine uses exclusively asyncpg for runtime data access. SQLAlchemy models in models.py (316 lines) are used only for Alembic migrations, not runtime queries — so there is no true "dual pattern." However, schema changes must be coordinated between Alembic migrations and 99+ asyncpg SQL strings, creating a maintenance risk. The fq_table() pattern with _PROTECTED_TABLES whitelist provides defense in depth.

Review note: Downgraded from P1 because there is not a dual runtime data access pattern — SQLAlchemy models are schema-only. The concern about schema coordination is legitimate but subsumed by ARCH-01's decomposition.

Recommended fix: Create a Repository layer that encapsulates all asyncpg SQL, with MemoryEngine calling repository methods instead of raw SQL strings. This would naturally emerge from ARCH-01 decomposition.

P2 ARCH-03 — http.py is a 4200-line monolithic API module combining routes, models, and business logic → Founder view

File: hindsight-api/hindsight_api/api/http.py (4,230 lines, 138 function definitions)

Technical description: http.py combines FastAPI route definitions, Pydantic request/response models, authentication middleware, and business logic in a single file. The file is well-structured internally with clear sections, but navigation and isolated testing are difficult.

Recommended fix: Split into module-based routers following FastAPI's APIRouter pattern: routers/retain.py, routers/recall.py, routers/reflect.py, routers/banks.py, routers/documents.py, routers/admin.py. Keep models in a separate models/ module.

P2 ARCH-04 — config.py is 1300 lines with 100+ fields and manual env parsing → Founder view

File: hindsight-api/hindsight_api/config.py (1,308 lines, 178 os.getenv/os.environ calls)

Each new configuration option requires changes in 3 places: ENV_ constant, DEFAULT_ constant, and from_env() assignment. ConfigFieldAccessProxy is a well-designed access control layer that prevents misconfiguration.

Recommended fix: Refactor into configuration groups (e.g., LLMConfig, EmbeddingsConfig, RetainConfig) using pydantic-settings or similar typed configuration library.

Scaling Findings

4 findings: 1 P1 (no rate limiting), 3 P2. The internal semaphores provide process-level backpressure but lack per-tenant fairness and per-second rate limiting.

P1 SCA-01 — No rate limiting on LLM API calls — burst traffic can exhaust provider quotas → Founder view

File: hindsight-api/hindsight_api/engine/memory_engine.py

Technical description: No rate limiting middleware exists at the FastAPI layer. Internal semaphores (_global_llm_semaphore=32, _search_semaphore=32, _put_semaphore=5) provide process-level concurrency limits, but any single tenant can consume ALL semaphore slots. No per-second/per-minute/per-hour rate limiting exists. No tenant-level fairness in semaphore scheduling.

Compound risk: Combined with SEC-03 (no CORS + no rate limiting at HTTP layer) and SEC-01 (default no-auth), cost and availability are unguarded for any internet-reachable deployment.

Recommended fix: Add request rate limiting at the FastAPI middleware layer (e.g., slowapi). Implement fair scheduling in the worker to prevent one tenant from monopolizing slots. Consider per-tenant quotas for LLM calls.

P2 SCA-02 — Connection pool max size (100) may be insufficient under high concurrency

File: hindsight-api/hindsight_api/config.py (DEFAULT_DB_POOL_MAX_SIZE=100)

Technical description: With recall_max_concurrent=32, worker connections, and health checks, 100 concurrent connections is reasonable for PostgreSQL. However, no circuit breaker pattern exists for database connection failures. Under load, degraded connections could exhaust the pool.

Recommended fix: Add connection pool metrics/logging. Consider implementing a circuit breaker. Make pool size more configurable based on deployment scale.

P2 SCA-03 — Embedding and reranking model loads are synchronous in MemoryEngine.initialize()

File: hindsight-api/hindsight_api/engine/memory_engine.py:1203

Technical description: init_embeddings() and init_cross_encoder() load models during initialize(). The lazy_reranker flag can defer cross_encoder init, but embeddings are always synchronous (~5-15 seconds for local models).

Recommended fix: Add lazy initialization for the embedding model as well. External embedding providers skip local loading entirely, so this only affects local model deployments.

P2 SCA-04 — No request body size limiting middleware on API endpoints found by spot-check

File: hindsight-api/hindsight_api/api/http.py:1797

Technical description: No global request body size limiting middleware exists. File uploads have per-batch size limits (file_conversion_max_batch_size_mb=50MB), but general JSON request bodies (retain/recall/reflect) have no size limit. Combined with SEC-03 (no rate limiting), an unauthenticated client can send unlimited large payloads.

Recommended fix: Add request body size limiting middleware. Configure limits via environment variables (e.g., 10MB for JSON, 100MB for file uploads).

Dependency Health Findings

3 findings: 1 P1 (torch as required dep), 1 P2, 1 PASS. The P1 is a deployment efficiency issue that affects all production images.

P1 DEP-02 — sentence-transformers and torch included as required dependencies → Founder view upgraded from P2

File: hindsight-api/pyproject.toml (lines 49-51)

Technical description: sentence-transformers>=3.3.0 and torch>=2.6.0 are listed as required dependencies. This means every production deployment — including those using external embedding providers (OpenAI, Anthropic) — must install a ~2GB dependency that is never used at runtime. The Docker INCLUDE_LOCAL_MODELS=false build arg can exclude model files, but the Python package still installs torch regardless.

Impact: (1) Docker image size inflated by ~2GB for ALL deployments, (2) torch has significant security surface area, (3) combined with SEC-03 and SCA-01, deployments that never use local models pay both cost and security overhead.

Recommended fix: Move sentence-transformers and torch to an extras_require group: pip install hindsight-api[local-models]. Make local embedding models opt-in rather than default.

P2 DEP-01 — Transitive dependency pins in pyproject.toml for CVE mitigations

File: hindsight-api/pyproject.toml

Technical description: Dependencies like pyasn1>=0.6.2, urllib3>=2.6.3, langchain-core>=1.2.5, filelock>=3.20.1, authlib>=1.6.6, aiohttp>=3.13.3 are pinned with CVE fix comments. These are transitive dependencies listed as direct dependencies to force specific versions.

Recommended fix: Use pip-audit or safety in CI for vulnerability detection. Consider a requirements-constraints file for version overrides instead of adding transitive deps to direct dependencies.
